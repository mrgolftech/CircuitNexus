## 中间产物沿革
1. **命名阶段**：HardBuddy → CircuitNexus（曾讨论 CircuitNex、ElecWeave、EDAvelis 等；均不再用）。
2. **Logo 第一阶段**：蓝绿芯片/PCB 多线图形，视觉复杂；用户否决。
3. **Logo 第二阶段**：黑金六边开放 C 与内部三线路。用户要求修正上两根线局部线宽不一致，改为等宽并使用 45° PCB 走线。
4. **Logo 第三阶段**：重新矢量化，产生横排 SVG、图形 SVG、透明 PNG、Windows ICO、Favicon。位图参考与 SVG 重建仍需最终像素级差异人工复核。
5. **主题阶段**：已有 HardBuddy 深色/亮色工作台截图作为布局来源；明确两套金色系 Token 和交互/排版限制。
6. **背景阶段**：先输出纯 PNG 预览，后明确要求 SVG；最终交付完整背景/透明纹理的深浅各两张 SVG，再导出 PNG 预览。
7. **设计板阶段**：分别生成亮色与暗色图形化设计规范图；以 Markdown/Token 中的数值作为工程约束，设计板为表达稿。
8. **本仓库阶段**：将确认的 Logo、主题、工程规范纳入公开 GitHub 版本管理。

## 后续不要重复讨论的事项
- 英文名大小写与中文名已固定；
- 不再使用旧 HardBuddy Logo/蓝绿主风格；
- 三条内部走线不可忽粗忽细，不可在拐角使用圆弧；
- 欢迎背景 SVG 不可成为内容页面的干扰层；
- 不能把规划的 EDA 能力描述成已做过工程验证。

如遇实际渲染/小尺寸可读性问题，允许提出变更，但须记录理由并更新规范、SVG、导出资产与版本。
